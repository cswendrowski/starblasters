# Sector Map HD — Live Port Handoff

**For the next session.** Self-contained brief to port the approved HD sector-map
prototype into the live game. Read this first; deeper rationale is in
`docs/sector_map_hd_scope_2026-06-02.md`.

---

## Mission

Replace the live native sector map with an HD version that keeps the chunky
pixel-art celestial bodies but renders all UI (text, node icons, boss markers,
buttons, menus) crisp at 1920×1080. The look is **already built and
Roman-approved in a dev lab** — your job is to turn that prototype into the live
screen and wire up the real gameplay interactions the lab stubs.

## The approach (read-and-rehost)

The live map renders everything in one Node2D. Rather than rewrite it, the lab
**embeds it in a SubViewport** and pulls the UI to HD:

- **Stays chunky (in the SubViewport):** the `_draw()` background (fill +
  starfield + asteroid glitter — baked, can't separate) + the instanced
  celestial scenes (planets/stars/asteroids) + **routes** (`Line2D`, left in so
  they render *behind* the planets — an HD-overlay line would draw over them).
- **Pulled to HD overlay (positioned at marker × 4):** all `Label`s, POI/boss
  icons, boss rings, buttons. The lab walks the embedded map, **hides** those
  nodes, and rebuilds crisp HD copies. Hit-testing is HD-native (the map's
  `_poi_hits` / `_boss_entries` × 4 vs the HD mouse).
- Node icons use the **hi-res glyphs in `graphics/sector/`** (battle/station/
  boss/hazard/unknown), keyed by the strip icon index, with the exact v3
  hover/transparency/coloring (rest white@icon_rest → hover green@0.9; boss
  state colors). See `_rehost_hover_icons` / `_process` in the lab.

## Port plan (recommended: wrap-in-place)

1. **New live host scene** `scenes/sector_map_hd.tscn` + script, modeled on the
   lab: `HdScreen.enter`, SubViewport(480) with the embedded `sector_map_v3`,
   ×4 TextureRect, HD overlay. **Lift the lab's rehost code verbatim** (labels,
   icons, boss dots/rings, hover `_process`, marker×4 button placement,
   HD-native hit-test). Keep the lab as-is for reference; don't break it.

2. **Add an "embedded" mode to `sector_map_v3`** (a flag set by the host before
   it runs):
   - Skip building its own `BottomBtnLayer` buttons.
   - Skip its `_unhandled_input` POI/boss transitions (the host owns input).
   - Use the SubViewport's own bg instead of the global
     `RenderingServer.set_default_clear_color` (so it doesn't tint the window).
   - **Guard the `_ready` side-effects so they run exactly once** — `_ready`
     does `save_to_disk`, self-repair hull regen, `_advance_if_complete`, music
     context. Decide whether the embedded map or the host owns these; do NOT
     double-apply (e.g. hull would regen twice).

3. **Wire the real interactions** (the lab stubs these):
   - **POI/boss click** → already calls the embedded map's
     `_on_poi_selected`/`_on_boss_selected`. Also drive the **selected-node
     label** (the lab hides + rehosts labels; the live selected label updates on
     selection — re-show/update an HD copy so the player sees the selection).
   - **DEPART** → call the real transition. In `sector_map_v3` see
     `_on_depart_pressed` (~line 2026) — it routes to combat/outpost/signal/
     hazard by the selected node type. Reuse that logic (or call into it) instead
     of the lab's toast.
   - **OPTIONS / Esc** → `OptionsOverlay.open(self)` (HD, already correct).
   - **MANAGE SHIP** → `SceneTransition.change_scene` to `manage_ship.tscn`,
     after `Run.set_meta("manage_ship_return", <this host scene path>)`.

4. **Remove the old in-map Manage Ship modal** from `sector_map_v3`
   (`_show_manage_ship_modal` / `_render_manage_ship_contents` / `_ms_*` helpers,
   ~lines 2207–2536) — `manage_ship.tscn` replaces it. Decide: keep the
   native-pinned no-bounty modal, or rebuild it HD in the host.

5. **Flip the route:** `scripts/sector_map_route.gd` `SECTOR_MAP_SCENE` → the new
   host scene. Add the host to `tools/parse_check.ps1`.

6. **(Optional) extract instead of wrap.** If the embedded-mode flags get messy,
   the cleaner long-term alternative is to split `sector_map_v3`'s art/markers/
   POI-data from its UI/input into a reusable `MapContent` node. More work; only
   do this if wrap-in-place fights you.

## Watch-items / gotchas

- **Don't break marker placement.** The map is entirely `Marker2D`-driven (see
  `docs/sectormap_labels.md`). HD positions = `marker.global_position × 4`.
- **New `class_name` scripts** aren't in `.godot/global_script_class_cache.cfg`
  until a rescan → they resolve in scene-boot but NOT in `-s` tool scripts or the
  **web export**. After adding one, run `godot --headless --import`.
- `sector_map_v3` has a **pre-existing non-fatal `"Invalid operands 'bool' and
  'float'"` console error** that fires even live — not from the port.
- The whole map→combat→outpost→map→boss loop must be retested (transitions +
  Run save + sector advance).
